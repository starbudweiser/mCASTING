1Overview

mCASTING is a macOS app for casting local AI voices. For any project that needs voices (game, video, voice-over, tutorial, trailer, audiobook), it lets you describe the characters, listen to a library of about 600 voices, pick one voice per character by ear, then hand the result to an AI agent or a generation script as a casting.json file.

What it does

  • Per-project casting, with sample lines and a language (French or English).
  • A library of 600 voice recipes, each with a French and an English sample.
  • Voice cloning from an audio file or a web link.
  • A Getting started guide adapted to the user's hardware.
  • Creature and animal voices: voice effects and generated cries.
  • A built-in MCP server that any agent can drive.

Principles

  • Local by default: Apple Silicon, macOS 15 or later; no data sent anywhere.
  • The human decides: an agent prepares and suggests, the person approves by ear.
  • One heavy job at a time (a lock shared by the app and the MCP server).
  • Nothing paid without consent: ElevenLabs cost is shown and confirmed for every generation.
  • Public app, MIT License, no dependency on the author's own tools.

It belongs to the DESKTOP MAC TOOLKIT, Starbudweiser's collection of Mac apps. Source code and notarized builds: github.com/starbudweiser/mCASTING.

2Architecture

The Swift code is split into three targets. Core holds all the business logic with no dependency on the interface: it is compiled into both the app and the MCP server, which therefore work on the same files with the same rules.

App (SwiftUI)

Windows, Getting started guide, casting, library, cloning, models, settings, splash, automatic updates, 4 languages.

Core (shared)

Data model, JSON storage, speech engine, library, import and export, creatures, remote voices, agent setup.

MCP (executable)

mcasting-mcp: JSON-RPC over stdio, 11 tools, one resource, one prompt. Shipped inside the app bundle.
Data: ~/Library/Application Support/mCASTING (JSON + audio) · Engine: isolated Python 3.12 (uv) + mlx-audio · Models: Hugging Face

Main flow

Project→Characters and lines→Voice model choice→Library→Casting by ear→casting.json→Line generation

Characters arrive three ways: typed in the app, imported (mcasting-project/1 JSON, CSV, or "NAME: line" text), or sent by an agent through the MCP server. The agent or script that produces the final lines reads the written casting.

4Data and storage

All data lives in ~/Library/Application Support/mCASTING/. The development edition (bundle id fr.stephan.mcasting.dev) uses mCASTING-dev, so it never touches real data. The MCASTING_HOME environment variable overrides the folder (tests, isolated MCP server).

File or folderContent
projects.jsonProjects: name, language, output folder, characters and casting.
voices.jsonLibrary: recipes, per-language samples, cloned voices, remote voices.
favorites.jsonStarred samples.
setup.jsonGetting started progress and choices.
jobs.jsonRunning generation jobs (automatic resume).
compute.lockHeavy-compute lock, shared with the MCP server.
audio/lib/Library samples (.m4a).
audio/preview/, audio/sfx/Line trials, rendered effects, creature cries.
audio/srv/, audio/el/Samples of network-server and ElevenLabs voices.
engine/uv, private Python environment (venv) and model cache.
Tolerant decoding. Structures are decoded field by field (decodeIfPresent): a field added by a newer version, or missing from an old file, never wipes the other settings. Data model additions are always optional.

Secrets are never written to these files: a voice server key and the ElevenLabs key go to the macOS Keychain (service mCASTING, accounts server and elevenlabs). The ElevenLabs key can also come from the ELEVENLABS_API_KEY environment variable.

5Data model

Voice — a library voice

FieldPurpose
id, nameStable id and display name ("Lucien 1").
gender, age, pitch, tone, speciesSearch criteria: man, woman, child, animal, creature; young, adult, senior; low, medium, high; tone (dry, warm…); species for animals and creatures.
recipeFull English description, used by Qwen3-TTS VoiceDesign.
engineqwen3-voicedesign, qwen3-base (cloned voice), server or elevenlabs.
samplesOne sample per language, keyed by ISO 639-1 code: {"fr": "lib/….m4a", "de": "…"}. Any language fits, with no migration.
refAudio, refText, sourceCloned voice: reference excerpt, its exact transcript, its origin.
remoteModel, remoteVoiceServer or ElevenLabs voice: model and voice name (or id).

Character — a character in a project

FieldPurpose
id, key, name, role, notesIdentity. key is the id in the source project, used to merge successive imports.
lines, altLines, lineCountSample lines in the project's main language, lines per language (code → list), total line count.
currentVoice the project already uses (description, engine, samples), for comparison.
voiceID, styleChosen voice and default emotion direction (neutral, tired, happy, angry, or free text).
kindhuman, creature or animal.
fx, sfxChosen voice effect and generated cry, for non-human characters.

Project

id, name, lang (main language, the language of lines), langs (one or two languages, main first), active (listening language), folder (where casting.json is written), characters. A 1.x project (no langs) is read as French + English, with its old language as the listening language. Changing the main language files the lines already entered under their original language (altLines). Deleting a project removes it from mCASTING without touching its folder or its casting.json.

Lang and Languages (2.0)

Lang is an open ISO 639-1 code, encoded as a plain string (1.x compatible). Languages.swift describes 23 languages (native name, English name, two sample sentences) and each model's languages: Qwen3 10, Fish Audio 13, Chatterbox multilingual and OmniVoice 23. A project's languages are the voice creator's; on-demand listening covers the languages of every installed acting model.

6Local speech engine

When first needed, the app downloads uv, creates a private Python 3.12 environment in engine/venv and installs mlx-audio into it (plus yt-dlp for cloning from a link). Nothing is installed system-wide. Models are downloaded from Hugging Face on demand, with resume and file checks; their status shows on the TTS models page.

Hardware fit

Hardware reads the chip, memory and free disk space, then rates the Mac Light, Comfort or Studio. A model is suggested when it needs less than 50% of memory, possible up to 70%, and hidden above.

7Voice library and acting model

The library holds 600 recipes built by combination (gender × age × register × tone, plus animals and creatures). Each recipe is rendered by Qwen3-TTS VoiceDesign in every project language (plus languages added to the whole library), language by language, with a per-language pause (setup.json: extraLangs, pausedLangs). A language already computed is never redone. The recipes' "French-speaking" wording is replaced by the computed language. Generation runs in the background and resumes on its own after an interruption.

Two separate roles

"Designer" model

Only some models can create a voice from a description (Qwen3 VoiceDesign). The library is always made by that model, so every voice has a fixed timbre, the one heard in its samples.

Acting model

The model picked by ear (Qwen3 Base, Fish Audio, Chatterbox, OmniVoice) speaks the lines by cloning the chosen voice's sample. The acting model can change without regenerating the library.

Native accent in each language, listening in all the others

To speak a line in a language, mCASTING clones the voice's sample in that language when it exists. Otherwise (a language outside the project), it clones the main language's sample with the first installed acting model that speaks the requested language (Languages.actingModel): this is on-demand listening, cached in audio/cache/<voice>.<language>.<hash>.m4a (FNV-1a hash of text, emotion and model; no cache in Expressive mode). Cloning a sample into another language keeps the timbre but carries its accent too, so another language's sample is only a last resort. A recipe is never re-run through VoiceDesign for a new line: the model would draw a new timbre every time.

Line trials

  • Faithful: the sample's exact timbre, without emotion.
  • Expressive: the emotion direction (neutral, tired, happy, angry or free text) is applied by the acting model.
  • Compare: A/B listening of two voices on the same line.

8Voice cloning

  1. Source: an audio or video file (WAV, MP3, M4A, AIFF…) or a web link (YouTube and other sites, audio only, through yt-dlp).
  2. Pick a 5 to 15 second excerpt.
  3. Automatic transcription of the excerpt (mlx-audio speech recognition), editable.
  4. Required checkbox: the user certifies they have the right to use this voice.
  5. The voice is added to the library with engine: "qwen3-base", refAudio and refText.
mCASTING does not check where a voice comes from: the user remains responsible for the rights to any cloned or imported voice.

9Getting started guide

The guide opens on first launch, for every new project, and from the Getting started… menu. One question per screen, the recommended choice preselected, "Later" always available. Its progress is kept in setup.json (SetupState).

StepQuestionWhat happens
1. ProjectWhat is your project called?Name, output folder, voice language; or open an existing project.
2. PreparationShould an AI prepare your project?The AI you already use (skill and MCP setup), a local AI (Ollama, LM Studio), or manual description.
3. DialogueDo you already have the lines?JSON, CSV or text import; optional character analysis by the local AI.
4. VoicesWhere should voices be made?On this Mac (models fit to the hardware), on another computer, or with an online service.
5. ListeningWhich model do you prefer?Download of the checked models, the same lines spoken by each, choice of the acting model.
CreaturesWhich voices for your creatures?Shown only when there are creatures or animals: suggested voices, effects, cries.
6. LibraryBuild the library?Generation of the 600 voices in the background.

Steps adapt to the chosen mode: Mac = all; network server = no comparison listening; online service = no listening and no library; quick project = project, preparation, dialogue (and creatures).

10AI assistants: skill, MCP, dialogue analysis

mCASTING keeps two roles clearly apart: the AI assistant (text: it reads the project, describes characters, prepares lines) and the voice model (audio: it speaks).

Agent setup (AgentInstaller)

AgentSkillMCP server
Claude Code~/.claude/skills/mcasting/SKILL.mdclaude mcp add --scope user mcasting -- <mcasting-mcp>
Codex~/.codex/skills/mcasting/[mcp_servers.mcasting] section of config.toml
Cursor—~/.cursor/mcp.json
Claude Desktop—mcpServers in claude_desktop_config.json

Every settings file is backed up before it is changed (<file>.mcasting-backup-<date>), existing entries are kept, and setup asks for confirmation. The MCASTING_AGENT_HOME variable redirects setup to a test folder.

The mcasting skill

Shipped with the app (Resources/skill/mcasting/SKILL.md), it teaches the agent how to structure a project: one entry per speaking character, a role that says how they should sound, the kind (human, creature, animal), 5 to 20 varied lines per language; then MCP import, casting left to the human, and generation from casting.json.

Analysis by a local AI (DialogueAnalyzer)

  • Text server discovery: Ollama (127.0.0.1:11434), LM Studio (127.0.0.1:1234), or MCASTING_LLM_BASE, through /v1/models; audio models are filtered out.
  • Suggested model: a recent instruction model (Qwen3, Qwen2.5, Mistral, Llama, Gemma).
  • Analysis in batches of 12 characters: gender, age, kind and a one-sentence voice description; tolerant reading of JSON answers.
  • The result fills the role or the notes; an existing casting is never touched.

Simple imports

CSV (character; line; language, separated by semicolon, tab or comma, header skipped) and text (NAME: line, all-caps names reformatted) are converted to mcasting-project/1.

11Creatures, animals and sound effects

A character of kind creature or animal (given by the import or inferred from its name and role) gets dedicated treatment.

  • Suggested voices: three library voices, chosen from the recognised species (dragon, troll, goblin, ghost, robot, cat…) and the described mood.
  • Voice effects (CreatureFX): three presets per family — big (very deep, growling, cavernous), small (high, squeaky, sly), ghostly (echo, whisper, deep), mechanical (metal, radio, deep) and middle. Rendered offline with AVAudioEngine (pitch, speed, distortion, reverb, echo).
  • Cries: a wordless sound effect generated by Stable Audio 3 Small SFX (audio/sfx/<project>-<character>-<seed>.m4a), to replay or redo with another seed.

Each effect has an ffmpeg equivalent (resampling for pitch, compensated tempo, echo, acrusher for distortion), written to casting.json (fx_ffmpeg) so the final lines sound like what the person chose.

12Voices made elsewhere: network server and ElevenLabs

Network server (VoiceServer)

Any server compatible with OpenAI's speech API (mlx-audio server, LocalAI, Kokoro-FastAPI…): /v1/models, /v1/audio/voices, /v1/audio/speech. Optional key in the Keychain.

  • Library built on the server: if the server has a VoiceDesign model, the 600 recipes are rendered there.
  • Ready-made voices: a model's voices (for example Kokoro's 54) are imported with a sample in each project language, made on the server; ids srv-<host>-<voice>, gender guessed from the prefix (af_, am_).
  • Faithful mode (cloning) stays on the Mac: these servers do not receive audio excerpts over the network.

ElevenLabs (paid)

  • Free calls: account balance (/v1/user/subscription) and the voice list with previews (/v1/voices); voices imported with id el-<voice_id>.
  • Paid call: /v1/text-to-speech/{id}, model eleven_multilingual_v2. Before each generation the app shows the character count and the estimated cost (0.4 credit per character, measured) and waits for confirmation.

13Exchange formats

Import: mcasting-project/1

{
  "format": "mcasting-project/1",
  "name": "My game",
  "languages": ["en", "fr"],
  "folder": "/path/to/project",
  "characters": [{
    "id": "hero", "name": "Hero",
    "role": "young deadpan adventurer, calm voice",
    "kind": "human",
    "notes": "accent, relationships…",
    "line_count": 383,
    "lines": {"fr": ["…"], "en": ["…"]},
    "current_voice": {"description": "…", "engine": "…",
                      "samples": [{"file": "/…/sample.mp3", "text": "…"}]}
  }]
}

Re-importing is safe: characters are matched by id then by name, new ones are added, existing ones updated, and a casting already done is never erased. dry_run previews the result.

Output: casting.json (mcasting/1)

{
  "format": "mcasting/1", "project": "My game", "lang": "en", "languages": ["en", "fr"],
  "characters": { "hero": {
    "name": "Hero", "voice_id": "man-adult-medium-1",
    "engine": "qwen3-voicedesign", "recipe": "An English-speaking person…",
    "style": "tired, low energy",
    "samples": {"fr": "/…/lib/….fr.m4a", "en": "/…/lib/….en.m4a"},
    "acting_model": "qwen3-base",
    "lines_alt": {"fr": ["…"]},
    "sfx": "/…/sfx/….m4a", "fx": "big.deep", "fx_ffmpeg": "asetrate=…",
    "remote_model": "…", "remote_voice": "…", "server": "http://…"
  }}
}
FieldHow the agent or script uses it
samples.<lang> + acting_modelSpeak each line by cloning the sample in its language with the acting model.
ref_audio / ref_textCloned voice: reference excerpt and transcript.
timbre_ref_audioLast resort when no sample exists in the language.
engine: "server"POST <server>/v1/audio/speech with remote_model and remote_voice.
engine: "elevenlabs"Paid: state the character count and get approval before generating.

14MCP server

mcasting-mcp is a JSON-RPC executable over stdio, shipped in mCASTING.app/Contents/MacOS/. It shares the Core code and the data files with the app. Manual setup:

claude mcp add mcasting -- "/Applications/mCASTING.app/Contents/MacOS/mcasting-mcp"
ToolPurpose
get_import_guideStart here: the import format and how to build it from the project's files.
import_projectImport or update a project (project_json or path, dry_run, mode).
export_projectExport a project in the same format.
list_languagesLanguages a project can use (library), listening languages (installed models), each project's languages.
list_projects, create_project, set_project_languagesList projects with progress and languages; create a project (languages: "de,en", folder); change its languages.

The server also exposes the mcasting://import-guide resource and the import_project prompt. Incoming calls are listed in the Settings log.

15Interface, languages and accessibility

The interface follows the Flat Mat design (matte, flat, 1-pixel rules, 12 and 8 radii), detailed in the user interface guide. It is fully translated into French, English, Spanish and Italian (L10n.swift, same keys in all four tables, no hard-coded text); the language follows the system, with English as fallback. Voice languages are independent from the interface language: their names show in their own script, translated on hover by macOS.

  • Light and dark themes; "Reduce motion" is honoured (still splash).
  • The main window opens centred on the pointer's screen, at the last size chosen.
  • Menu bar icon: active project, running job, open, Getting started, About, Quit.
  • Buttons are never nested inside a clickable card, so VoiceOver and accessibility tools reach every action.

16Build, signing, release, updates

./build_app.sh          # build, sign and install the app
DEV=1 ./build_app.sh    # development edition (separate id and data)
./release.sh "notes"    # Apple notarization, zip, tag and GitHub release
  • build_app.sh builds two executables with swiftc (the app and mcasting-mcp, target arm64-apple-macos15), copies resources and the skill, then signs with a stable certificate so macOS keeps permissions from one build to the next.
  • release.sh refuses to publish with uncommitted changes or when the version already exists; the version comes from CFBundleShortVersionString.
  • Automatic updates: daily check of GitHub releases, Developer ID signature check, replacement then relaunch — never during a job. Settings: an "install automatically" switch and a manual check button.

17Testing, known limits and safety rules

Verified

  • Correct French cloning with Fish Audio, Chatterbox multilingual, OmniVoice and Qwen3 (Whisper transcripts).
  • End-to-end comparison listening, creature cries, voice suggestions, effect rendering and valid ffmpeg filters.
  • Setup into all four agents in a test folder, with backups, without touching real configurations.
  • Analysis by a local AI (OpenAI-compatible test server), CSV and text conversion.
  • Network server (mlx-audio server): voice designed from a description, 54 Kokoro voices, a French line.
  • ElevenLabs: free calls only (balance, import of 38 voices).

Not verified or limits

  • Paid ElevenLabs generation (not run, to spend no credits).
  • Real Ollama and LM Studio (same protocol as the one tested).
  • Cloning does not go through a network server: it stays local.
  • Fish Audio Drama 3 weighs 22 GB and needs a lot of memory; its license requires attribution for commercial use.

Safety rules

  • No secret in files or in the repository: Keychain or environment variable.
  • No spending without a costed confirmation.
  • Any change to another app's settings is backed up and confirmed.
