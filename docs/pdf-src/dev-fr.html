1Présentation

mCASTING est une application macOS de casting de voix IA locales. Pour tout projet qui a besoin de voix (jeu, vidéo, voix off, tutoriel, bande-annonce, livre audio), elle permet de décrire les personnages, d'écouter une bibliothèque d'environ 600 voix, de choisir une voix par personnage à l'oreille, puis de transmettre le résultat à un agent IA ou à un script de génération sous la forme d'un fichier casting.json.

Ce qu'elle fait

  • Casting par projet, avec répliques d'exemple et langue (français ou anglais).
  • Bibliothèque de 600 recettes de voix, un extrait FR et un extrait EN chacune.
  • Clonage d'une voix à partir d'un fichier audio ou d'un lien web.
  • Guide « Premiers pas » adapté au matériel de l'utilisateur.
  • Voix de créatures et d'animaux : effets de voix et cris générés.
  • Serveur MCP intégré, pilotable par n'importe quel agent.

Principes

  • 100 % local par défaut : Apple Silicon, macOS 15 ou plus récent ; aucun envoi de données.
  • L'humain choisit : un agent prépare et propose, la personne valide à l'oreille.
  • Un seul calcul lourd à la fois (verrou partagé entre l'appli et le serveur MCP).
  • Rien de payant sans accord : le coût ElevenLabs est affiché et confirmé à chaque génération.
  • Application publique, licence MIT, sans dépendance aux outils de l'auteur.

Elle fait partie du DESKTOP MAC TOOLKIT, la collection d'applications Mac de Starbudweiser. Code source et versions notarisées : github.com/starbudweiser/mCASTING.

2Architecture générale

Le code Swift est réparti en trois cibles. Core contient toute la logique métier et n'a aucune dépendance à l'interface : il est compilé à la fois dans l'application et dans le serveur MCP, qui travaillent donc sur les mêmes fichiers avec les mêmes règles.

App (SwiftUI)

Fenêtres, guide « Premiers pas », casting, bibliothèque, clonage, modèles, réglages, splash, mise à jour automatique, 4 langues.

Core (partagé)

Modèles de données, stockage JSON, moteur de synthèse, bibliothèque, import et export, créatures, voix distantes, installation des agents.

MCP (exécutable)

mcasting-mcp : JSON-RPC sur stdio, 11 outils, une ressource, une invite. Embarqué dans le paquet de l'appli.
Données : ~/Library/Application Support/mCASTING (JSON + audio) · Moteur : Python 3.12 isolé (uv) + mlx-audio · Modèles : Hugging Face

Flux principal

Projet→Personnages et répliques→Choix du modèle de voix→Bibliothèque→Casting à l'oreille→casting.json→Génération des répliques

Les personnages arrivent de trois façons : saisis dans l'appli, importés (JSON mcasting-project/1, CSV, texte « NOM : réplique ») ou envoyés par un agent via le serveur MCP. Le casting écrit est relu par l'agent ou le script qui produit les répliques définitives.

Lecture tolérante. Les structures sont décodées champ par champ (decodeIfPresent) : un champ ajouté par une version plus récente, ou absent d'un ancien fichier, ne fait jamais perdre les autres réglages. Les ajouts au modèle de données sont toujours facultatifs.

Lang et Languages (2.0)

Lang est un code ISO 639-1 ouvert, encodé en simple chaîne (compatible 1.x). Languages.swift décrit 23 langues (nom natif, nom anglais, deux phrases d'extrait) et les langues de chaque modèle : Qwen3 10, Fish Audio 13, Chatterbox multilingue et OmniVoice 23. Les langues d'un projet sont celles du créateur de voix ; l'écoute à la demande couvre les langues de tous les modèles de jeu installés.

6Moteur de synthèse local

Au premier besoin, l'application télécharge uv, crée un environnement Python 3.12 privé dans engine/venv et y installe mlx-audio (ainsi que yt-dlp pour le clonage depuis un lien). Rien n'est installé dans le système. Les modèles sont téléchargés depuis Hugging Face à la demande, avec reprise et vérification des fichiers ; leur état est affiché dans la page Modèles TTS.

7Bibliothèque de voix et modèle de jeu

La bibliothèque compte 600 recettes construites par combinaison (genre × âge × registre × ton, plus des animaux et des créatures). Chaque recette est rendue par Qwen3-TTS VoiceDesign dans chaque langue des projets (plus les langues ajoutées à toute la bibliothèque), langue par langue, avec pause par langue (setup.json : extraLangs, pausedLangs). Une langue déjà calculée n'est jamais refaite. La mention « French-speaking » des recettes est remplacée par la langue calculée. La génération tourne en arrière-plan et reprend seule après une interruption.

Deux rôles distincts

Modèle « créateur »

Seuls certains modèles savent créer une voix à partir d'une description (Qwen3 VoiceDesign). La bibliothèque est toujours fabriquée par ce modèle : chaque voix a ainsi un timbre fixe, entendu dans ses extraits.

Modèle de jeu

Le modèle choisi à l'écoute (Qwen3 Base, Fish Audio, Chatterbox, OmniVoice) dit les répliques en clonant l'extrait de la voix choisie. On peut changer de modèle de jeu sans régénérer la bibliothèque.

Accent natif dans chaque langue, écoute dans toutes les autres

Pour dire une réplique dans une langue, mCASTING clone l'extrait de cette langue s'il existe. Sinon (langue hors projet), il clone l'extrait de la langue principale avec le premier modèle de jeu installé qui parle la langue demandée (Languages.actingModel) : c'est l'écoute à la demande, gardée en cache dans audio/cache/<voix>.<langue>.<empreinte>.m4a (empreinte FNV-1a du texte, de l'émotion et du modèle ; pas de cache en mode Expressive). Cloner un extrait dans une autre langue garde le timbre mais transporte aussi l'accent : l'extrait d'une autre langue ne sert qu'en dernier recours. Une recette n'est jamais régénérée par VoiceDesign pour une nouvelle réplique, car le modèle tirerait un nouveau timbre à chaque fois.

Essais de répliques

  • Fidèle : timbre exact de l'extrait, sans émotion.
  • Expressive : la consigne d'émotion (neutre, fatigué, joyeux, colère ou texte libre) est appliquée par le modèle de jeu.
  • Comparer : écoute A/B de deux voix sur la même réplique.

8Clonage de voix

  1. Source : un fichier audio ou vidéo (WAV, MP3, M4A, AIFF…) ou un lien web (YouTube et autres sites, audio seul, via yt-dlp).
  2. Choix d'un extrait de 5 à 15 secondes.
  3. Transcription automatique de l'extrait (reconnaissance vocale mlx-audio), corrigeable.
  4. Case obligatoire : l'utilisateur certifie avoir le droit d'utiliser cette voix.
  5. La voix est ajoutée à la bibliothèque avec engine: "qwen3-base", refAudio et refText.
mCASTING ne vérifie pas l'origine des voix : l'utilisateur reste responsable des droits sur toute voix clonée ou importée.

9Guide « Premiers pas »

Le guide s'ouvre au premier lancement, à chaque nouveau projet et depuis le menu Premiers pas…. Une question par écran, le choix conseillé déjà sélectionné, « Plus tard » toujours possible. Son avancement est gardé dans setup.json (SetupState).

ÉtapeQuestionCe qui se passe
1. ProjetComment s'appelle votre projet ?Nom, dossier de sortie, langue des voix ; ou ouverture d'un projet existant.
2. PréparationVoulez-vous qu'une IA prépare votre projet ?IA déjà utilisée (installation du skill et du MCP), IA locale (Ollama, LM Studio) ou description manuelle.
3. DialoguesAvez-vous déjà les répliques ?Import JSON, CSV ou texte ; analyse facultative des personnages par l'IA locale.
4. VoixOù fabriquer les voix ?Sur ce Mac (modèles adaptés au matériel), sur un autre ordinateur, ou avec un service en ligne.
5. ÉcouteQuel modèle préférez-vous ?Téléchargement des modèles cochés, mêmes répliques dites par chacun, choix du modèle de jeu.

Les étapes s'adaptent au mode choisi : Mac = toutes ; serveur réseau = sans écoute comparée ; service en ligne = ni écoute ni bibliothèque ; projet rapide = projet, préparation, dialogues (et créatures).

10Assistants IA : skill, MCP, analyse des dialogues

mCASTING distingue clairement deux rôles : l'assistant IA (du texte : il lit le projet, décrit les personnages, prépare les répliques) et le modèle de voix (de l'audio : il parle).

Le skill mcasting

Livré dans l'appli (Resources/skill/mcasting/SKILL.md, en anglais), il apprend à l'agent à structurer un projet : un personnage par voix qui parle, un rôle qui dit comment il doit sonner, le type (humain, créature, animal), 5 à 20 répliques variées par langue ; puis l'import par MCP, le casting laissé à l'humain et la génération à partir de casting.json.

Analyse par une IA locale (DialogueAnalyzer)

  • Découverte des serveurs de texte : Ollama (127.0.0.1:11434), LM Studio (127.0.0.1:1234), ou MCASTING_LLM_BASE, par l'API /v1/models ; les modèles audio sont écartés.
  • Modèle conseillé : un modèle d'instructions récent (Qwen3, Qwen2.5, Mistral, Llama, Gemma).
  • Analyse par lots de 12 personnages : genre, âge, type et une phrase de description de voix ; lecture tolérante des réponses JSON.
  • Le résultat complète le rôle ou les notes ; le casting déjà fait n'est jamais touché.

Imports simples

CSV (personnage ; réplique ; langue, séparateur point-virgule, tabulation ou virgule, en-tête ignoré) et texte (NOM : réplique, les noms en capitales sont remis en forme) sont convertis au format mcasting-project/1.

11Créatures, animaux et bruitages

Un personnage de type creature ou animal (fourni par l'import ou déduit de son nom et de son rôle) reçoit un traitement dédié.

  • Voix suggérées : trois voix de la bibliothèque, choisies d'après l'espèce reconnue (dragon, troll, gobelin, fantôme, robot, chat…) et l'humeur décrite.
  • Effets de voix (CreatureFX) : trois préréglages par famille — gros (très grave, grondant, caverneux), petit (aigu, couinant, rusé), spectral (écho, murmure, grave), mécanique (métal, radio, grave) et intermédiaire. Rendu hors ligne par AVAudioEngine (hauteur, vitesse, distorsion, réverbération, écho).
  • Cris : bruitage sans paroles généré par Stable Audio 3 Small SFX (audio/sfx/<projet>-<perso>-<graine>.m4a), à rejouer ou à refaire avec une autre graine.

Chaque effet a son équivalent ffmpeg (rééchantillonnage pour la hauteur, tempo compensé, écho, acrusher pour la distorsion), écrit dans casting.json (fx_ffmpeg) pour que les répliques définitives sonnent comme ce que la personne a choisi.

12Voix fabriquées ailleurs : serveur réseau et ElevenLabs

Serveur du réseau (VoiceServer)

Tout serveur compatible avec l'API de synthèse d'OpenAI (mlx-audio server, LocalAI, Kokoro-FastAPI…) : /v1/models, /v1/audio/voices, /v1/audio/speech. Clé facultative dans le Trousseau.

  • Bibliothèque fabriquée sur le serveur : si le serveur a un modèle VoiceDesign, les 600 recettes y sont rendues.
  • Voix toutes prêtes : les voix d'un modèle (par exemple les 54 voix de Kokoro) sont importées avec un extrait dans chaque langue des projets, fabriqué sur le serveur ; identifiants srv-<hôte>-<voix>, genre déduit du préfixe (af_, am_).
  • Le mode Fidèle (clonage) reste sur le Mac : ces serveurs ne reçoivent pas d'extrait audio par le réseau.

ElevenLabs (payant)

  • Appels gratuits : solde du compte (/v1/user/subscription) et liste des voix avec leurs extraits (/v1/voices) ; voix importées avec l'identifiant el-<voice_id>.
  • Appel payant : /v1/text-to-speech/{id}, modèle eleven_multilingual_v2. Avant chaque génération, l'appli affiche le nombre de caractères et le coût estimé (0,4 crédit par caractère, mesuré) et attend une confirmation.

14Serveur MCP

mcasting-mcp est un exécutable JSON-RPC sur stdio, livré dans mCASTING.app/Contents/MacOS/. Il partage le code Core et les fichiers de données avec l'appli. Déclaration manuelle :

claude mcp add mcasting -- "/Applications/mCASTING.app/Contents/MacOS/mcasting-mcp"
OutilRôle

import_projectImporter ou mettre à jour un projet (project_json ou path, dry_run, mode).
export_projectExporter un projet au même format.

15Interface, langues et accessibilité

L'interface suit le design Flat Mat (mat, plat, filets d'un pixel, rayons 12 et 8), décrit en détail dans le dossier de l'interface graphique. Elle est entièrement traduite en français, anglais, espagnol et italien (L10n.swift, mêmes clés dans les quatre tables, aucun texte écrit en dur) ; la langue suit celle du système, avec l'anglais par défaut. Les langues des voix sont indépendantes de celle de l'interface : leurs noms s'affichent dans leur propre écriture, traduits au survol par macOS.

  • Thèmes clair et sombre ; option « Réduire les animations » respectée (splash fixe).
  • Fenêtre principale ouverte centrée sur l'écran du pointeur, à la dernière taille choisie.
  • Icône dans la barre de menus : projet actif, calcul en cours, ouvrir, Premiers pas, À propos, Quitter.
  • Les boutons ne sont jamais imbriqués dans une carte cliquable, pour que VoiceOver et les outils d'accessibilité atteignent chaque action.

16Compilation, signature, publication, mise à jour

./build_app.sh          # compile, signe et installe l'appli
DEV=1 ./build_app.sh    # édition de développement (identifiant et données séparés)
./release.sh "notes"    # notarisation Apple, zip, tag et release GitHub
  • build_app.sh compile deux exécutables avec swiftc (appli et mcasting-mcp, cible arm64-apple-macos15), copie les ressources et le skill, puis signe avec un certificat stable pour que macOS garde les autorisations d'un build à l'autre.
  • release.sh refuse de publier si des modifications ne sont pas commitées ou si la version existe déjà ; la version vient de CFBundleShortVersionString.
  • Mise à jour automatique : recherche quotidienne dans les releases GitHub, vérification de la signature Developer ID, remplacement puis relance — jamais pendant un calcul. Réglages : case « installer automatiquement » et bouton de recherche manuelle.

17Essais, limites connues et règles de sécurité

Vérifié

  • Clonage en français correct avec Fish Audio, Chatterbox multilingue, OmniVoice et Qwen3 (transcriptions Whisper).
  • Écoute comparée de bout en bout, cris de créatures, suggestions de voix, rendu des effets et validité des filtres ffmpeg.
  • Installation dans les quatre agents dans un dossier d'essai, avec sauvegardes, sans toucher aux vraies configurations.
  • Analyse par une IA locale (serveur d'essai compatible OpenAI), conversion CSV et texte.
  • Serveur réseau (mlx-audio server) : voix créée d'après sa description, 54 voix Kokoro, réplique française.
  • ElevenLabs : appels gratuits seulement (solde, import de 38 voix).

Non vérifié ou limites

  • Génération payante ElevenLabs (non lancée pour ne dépenser aucun crédit).
  • Ollama et LM Studio réels (le protocole est le même que celui testé).
  • Le clonage ne passe pas par un serveur réseau : il reste local.
  • Fish Audio Drama 3 pèse 22 Go et demande beaucoup de mémoire ; licence avec mention obligatoire pour un usage commercial.

Règles de sécurité

  • Aucun secret dans les fichiers ni dans le dépôt : Trousseau ou variable d'environnement.
  • Aucune dépense sans confirmation chiffrée.
  • Toute modification de la configuration d'un autre logiciel est sauvegardée et confirmée.
