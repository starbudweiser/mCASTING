mCASTING 2.0 · les langues de son choix

Maquettes des écrans qui changent. Chaque projet choisit 2 langues de base : la bibliothèque calcule ses extraits dans ces langues, sur la machine hôte ou le serveur de voix. Ensuite, n'importe quelle voix peut s'écouter dans n'importe quelle langue du moteur, calculée à la demande avec le même timbre. Les repères orange nouveau montrent ce qui change.

Ouvrir un projet existant

  • Deux langues par projet : la principale (celle du casting et des répliques) et une secondaire facultative. Une seule langue suffit pour un projet monolingue.
  • Avant de lancer, l'appli annonce ce qui est déjà calculé et ce qui reste : rien n'est refait d'un projet à l'autre, la bibliothèque est commune à tous les projets.
  • Les langues d'un projet restent modifiables dans sa fiche ; les extraits manquants sont alors calculés.

Données

Aujourd'hui2.0
enum Lang { fr, en }struct Lang : code ISO 639-1 (de, ja…) + catalogue (nom natif, code propre à chaque moteur : german pour Qwen, d pour Kokoro…). Nom affiché traduit par macOS dans la langue de l'interface.
Project.lang (une langue)Project.languages (principale + secondaire facultative). Anciens projets : [lang, l'autre de fr/en], sans perte.
Voice.samples["fr"/"en"]Inchangé : déjà indexé par code de langue, il accepte toutes les langues. Aucune migration de la bibliothèque.
Phrases et prénoms FR / EN dans le codeFichier Resources/langues.json : phrase type et prénoms pour chaque langue des moteurs.
—Cache des écoutes à la demande : audio/cache/<voix>.<langue>.<texte>.wav, comptabilisé dans la vue Bibliothèque.

Modules

  • Core / Languages (nouveau) : catalogue des langues, langues de chaque moteur, correspondance des codes.
  • LibraryGenerator : calcule les langues demandées par les projets (au lieu de Lang.allCases), avec avancement par langue, pause et reprise.
  • Écoute à la demande : réutilise le clonage de timbre entre langues qui existe déjà (échantillon de référence → nouvelle langue), plus le cache.
  • Import (CSV, texte, JSON) : la colonne langue accepte tout code ; répliques rangées par langue.
  • casting.json v2 : lang = principale, languages = langues du projet, samples par code. Les champs actuels restent : un lecteur v1 continue de fonctionner.
  • MCP : lang accepte tout code ; create_project prend languages ; nouvel outil list_languages (langues des moteurs installés).
  • Interface : sélecteur de langues (projet, guide), menu de langue du lecteur, couverture dans la Bibliothèque, langues par modèle. L'interface elle-même reste en 4 langues.

Limites

  • « Toutes les langues » = toutes celles des moteurs installés : 10 avec Qwen3-TTS en 2.0.
  • Une voix conçue en anglais garde parfois un léger accent dans une autre langue : c'est le comportement du clonage de timbre. L'appli le dit dans le menu d'écoute (ⓘ), dans la fiche d'aide et dans la documentation (4 langues).
  • Clonage avec émotion : Qwen3-TTS ne sait pas encore garder le timbre exact et jouer une émotion en même temps. Chaque moteur déclare ce qu'il sait faire (cloneWithEmotion) : dès qu'une version du modèle le permet, le mode Expressive garde le timbre exact, sans changer l'interface.
  • Calculer une nouvelle langue pour 600 voix prend du temps : la durée est mesurée et annoncée avant de lancer.
